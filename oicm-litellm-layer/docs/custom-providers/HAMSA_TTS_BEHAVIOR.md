## Authentication

**File**: `/app/app/auth.py`

The TTS service uses Fernet symmetric encryption for API key authentication. The client must send an encrypted token in the `x-api-key` header. The server decrypts it and compares against the secret.

```python
# /app/.env contains:
ENCRYPTION_KEY="pbFK_uqlqLoNHuoiuuQZykzoeK5S8oEGh63pSwNfec0="
SECRET_API_KEY="HuoiuuQZykzoeK5S8o"
```

The auth flow:
1. Server loads `ENCRYPTION_KEY` and `SECRET_API_KEY` from `.env`
2. Server creates a Fernet cipher from `ENCRYPTION_KEY`
3. Client sends `x-api-key` header with a Fernet-encrypted token
4. Server decrypts the token and compares to `SECRET_API_KEY`
5. If match, request proceeds; otherwise 401

The encrypted API key is generated by encrypting the `SECRET_API_KEY` with the `ENCRYPTION_KEY`:

```python
from cryptography.fernet import Fernet
cipher = Fernet("pbFK_uqlqLoNHuoiuuQZykzoeK5S8oEGh63pSwNfec0=".encode())
encrypted = cipher.encrypt("HuoiuuQZykzoeK5S8o".encode()).decode()
# Result: gAAAAABqVlrPWkz1L8WH_nCl_9RQiRi9t6mHDWUPYBNMRoDW6kR4osW54hL5UzWdmM0So3Ur1Fs2ktmqKxhmMwrFs2XOMXeU2DVJhwKf6a1e35MSpvws8nA=
```

All endpoints except `/health-check` and `/` require the `x-api-key` header.

The `hamsaTTS` class is a singleton (via `__new__` override). It loads:
- A tokenizer (AutoTokenizer from transformers)
- An audio tokenizer (BiCodecTokenizer from `hamsatts`)
- A vLLM AsyncLLMEngine for token generation
- Speaker profiles from `/app/speakers/` directory (each speaker is a `.pt` file containing global token IDs and semantic token IDs)

## Endpoints

### 1. POST `/tts/stream` - Text-to-Speech Synthesis

**File**: `/app/app/main.py`

This is the main TTS endpoint. It accepts a JSON request and returns a streaming audio response.

#### Request Model

```python
class TTSRequest(BaseModel):
    text: str                                    # Required: text to synthesize
    speaker: str                                 # Required: speaker name (e.g. "jasem")
    language_id: str                             # Required: language code (e.g. "ar")
    lang: Optional[str] = "ar"                   # Optional: language override
    mulaw: Optional[bool] = False                # Optional: mu-law encoding (8kHz) vs PCM (16kHz)
    stream: Optional[bool] = False               # Optional: streaming mode (no WAV header)
    dialect: Optional[str] = None                # Optional: dialect code ("ksa", "msa", "eng")
    expressiveness: Optional[float] = 1.0        # Optional: 0.0-2.0, controls temperature
    speed: Optional[float] = 1.0                 # Optional: 0.5-2.0, speech speed multiplier
```

#### Request Example

```bash
curl -X POST "http://s-cd2850fc-5870-4a57-89da-5e978eee66f4.adeo.svc.cluster.local:8080/tts/stream" \
  -H "x-api-key: gAAAAABqVlrPWkz1L8WH_nCl_9RQiRi9t6mHDWUPYBNMRoDW6kR4osW54hL5UzWdmM0So3Ur1Fs2ktmqKxhmMwrFs2XOMXeU2DVJhwKf6a1e35MSpvws8nA=" \
  -H "Content-Type: application/json" \
  -d '{
    "text": "مرحبا بك في اختبار تحويل النص إلى كلام.",
    "speaker": "jasem",
    "language_id": "ar",
    "mulaw": false,
    "stream": false,
    "dialect": "ksa"
  }'
```

#### Response

- **Content-Type**: `audio/wav`
- **Format**: StreamingResponse (FastAPI `StreamingResponse` with `media_type="audio/wav"`)
- **Audio Format** (when `mulaw=false`):
  - 16kHz, mono, 16-bit PCM WAV
  - Includes WAV header when `stream=false`
  - No WAV header when `stream=true` (raw PCM stream)
- **Audio Format** (when `mulaw=true`):
  - 8kHz, mono, mu-law encoded
  - Audio is resampled from 16kHz to 8kHz, then converted from linear PCM to mu-law via `audioop.lin2ulaw`

#### Internal Processing Flow

1. **Text preprocessing**: If `stream=false`, generate WAV header first (16kHz sample rate)
2. **Speaker resolution**: Look up `speaker` (case-insensitive) in the loaded speakers dictionary. If not found, raises KeyError
3. **Dialect resolution**: Use provided `dialect` (lowercased) or fall back to speaker's default dialect. If text is >80% English, override dialect to `"eng"`
4. **Expressiveness calculation**: Converts `expressiveness` (0.0-2.0) to temperature and semantic token flag:
   - 0.0 to 1.0: temperature = 0.1 + (expressiveness * 0.5), no semantic tokens
   - 1.0 to 2.0: temperature = 0.4 + ((expressiveness - 1.0) * 1.1), with semantic tokens
5. **Pause token splitting**: Text is split by `<pause_short>` and `<pause_long>` tokens. Newlines become `<pause_short>`. Short pauses generate 400-600ms of silence. Long pauses generate 800-1500ms of silence
6. **Sentence splitting**: Each text chunk is preprocessed by `TextPreprocessor.preprocess()` which normalizes text and splits into sentences (desired_length=400, max_length=450 characters)
7. **Token generation**: For each sentence, `model.stream_tokens_to_audio()` is called with:
   - temperature (from expressiveness)
   - batch_size=25
   - overlap_tokens=10
   - trim_ms=100.0
   - top_k=25
   - top_p=0.95
   - use_semantic_tokens (from expressiveness)
   - speed (from request)
8. **Audio output**: Each generated audio chunk is trimmed (silence from start), optionally resampled for mu-law, and yielded as `int16` bytes

#### Expressiveness Mapping

| expressiveness | temperature | use_semantic_tokens | Description |
|---|---|---|---|
| 0.0 | 0.1 | false | Most deterministic, flat |
| 0.5 | 0.35 | false | Mild variation |
| 1.0 (default) | 0.6 | false | Balanced |
| 1.5 | 0.95 | true | Expressive with semantic tokens |
| 2.0 | 1.5 | true | Most expressive, most random |

### 2. POST `/tts/voice_clone` - Extract Voice Tokens from Audio

**File**: `/app/app/main.py`

Extracts speaker tokens (global token IDs and semantic token IDs) from an audio file. This is step 1 of the two-step voice cloning process.

#### Request Model

```python
class VCRequest(BaseModel):
    audio_url: str       # Required: URL to the reference audio file
    prompt_text: str     # Required: transcript of the reference audio
```

#### Request Example

```bash
curl -X POST "http://s-cd2850fc-5870-4a57-89da-5e978eee66f4.adeo.svc.cluster.local:8080/tts/voice_clone" \
  -H "x-api-key: <encrypted_key>" \
  -H "Content-Type: application/json" \
  -d '{
    "audio_url": "https://example.com/reference.wav",
    "prompt_text": "This is the transcript of the reference audio."
  }'
```

#### Response

Returns the extracted voice tokens as JSON. The response contains `global_token_ids` and `semantic_token_ids` that can be used in the `/tts/load_voice_cloning` endpoint.

#### Internal Flow

1. Calls `model.voice_clone_from_audio(audio_url, prompt_text)`
2. The method downloads the audio from the URL
3. Runs it through the BiCodecTokenizer to extract global and semantic tokens
4. Returns the token arrays

### 3. POST `/tts/load_voice_cloning` - Register a Cloned Voice

**File**: `/app/app/main.py`

Registers pre-extracted speaker tokens as a named speaker in the model's in-memory speaker dictionary. This is step 2 of the two-step voice cloning process.

#### Request Model

```python
class VCLoadRequest(BaseModel):
    speaker_id: str                                                    # Required: name for the new voice
    global_token_ids: Union[List[int], List[List[int]], List[List[List[int]]]]
    semantic_token_ids: Union[List[int], List[List[int]], List[List[List[int]]]]
    dialect: str = "msa"                                               # Optional: dialect code
    prompt_text: str = ""                                              # Optional: reference transcript
```

#### Request Example

```bash
curl -X POST "http://s-cd2850fc-5870-4a57-89da-5e978eee66f4.adeo.svc.cluster.local:8080/tts/load_voice_cloning" \
  -H "x-api-key: <encrypted_key>" \
  -H "Content-Type: application/json" \
  -d '{
    "speaker_id": "my_custom_voice",
    "global_token_ids": [[1, 2, 3], [4, 5, 6]],
    "semantic_token_ids": [[10, 20], [30, 40]],
    "dialect": "ksa",
    "prompt_text": "Reference transcript"
  }'
```

#### Response

Returns confirmation that the speaker was added.

#### Internal Flow

1. Calls `model.add_speaker(speaker_id, torch.tensor(global_token_ids), torch.tensor(semantic_token_ids), dialect, prompt_text)`
2. The speaker is registered in the `model.speakers` dictionary (keyed by lowercased `speaker_id`)
3. After registration, the new voice is immediately usable in `/tts/stream` by passing `speaker="my_custom_voice"`

**Important**: The registered speaker exists only in the model's in-memory state. If the pod restarts, custom voices are lost and must be re-registered.

## Dialect Support

The following dialect codes are supported:
- `msa` - Modern Standard Arabic (default for most speakers)
- `ksa` - Saudi Arabian dialect
- `eng` - English (auto-detected if text is >80% English)
- Other dialects may be available per-speaker (stored in speaker profile)

## Model Architecture

**File**: `/app/app/hamsaTTS.py`

The `hamsaTTS` class is based on Spark-TTS architecture, adapted for Arabic:

```python
class hamsaTTS:
    """
    Spark-TTS for text-to-speech generation using VLLMAsyncEngine
    for real-time token streaming.
    Implemented as a singleton.
    """
```

Key components:
- **Tokenizer**: `AutoTokenizer` from transformers (for text tokenization)
- **Audio Tokenizer**: `BiCodecTokenizer` from `hamsatts` (for audio encoding/decoding)
- **LLM Engine**: `AsyncLLMEngine` from vLLM (for autoregressive token generation)
- **Sample Rate**: 16000 Hz (native), 8000 Hz (mu-law mode)

The model uses a two-stage process:
1. **Token generation**: The LLM generates discrete audio tokens autoregressively from the input text, conditioned on speaker tokens
2. **Audio synthesis**: The BiCodecTokenizer decodes the generated tokens back into audio waveforms

The `stream_tokens_to_audio()` method is an async generator that yields audio chunks as they are generated, enabling real-time streaming.

## Text Preprocessing

**File**: `/app/app/text_preprocessor.py`

Before synthesis, text goes through preprocessing:
1. **Arabic number conversion**: `ArabicNumberToWord.replace_numbers_with_words()` converts numeric digits to Arabic words
2. **Sentence splitting**: `txtsplit` library splits long text into manageable chunks
3. **Normalization**: Various text normalization steps based on dialect
4. **Chunking**: Sentences are limited to ~400-450 characters

## Pause Token Support

The TTS supports inline pause tokens in the text:

| Token | Effect |
|---|---|
| `<pause_short>` | 400-600ms of silence (randomized) |
| `<pause_long>` | 800-1500ms of silence (randomized) |
| `\n` (newline) | Treated as `<pause_short>` |

These tokens allow clients to control pacing and rhythm in the synthesized speech.
