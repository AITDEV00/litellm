    • 1. Goal

    LiteLLM OpenRouter-Compatible Model Discovery¶

    Design and Implementation Instructions¶

    Status: Implementation design
    Target: Add an OpenRouter-compatible GET /api/v1/models capability-discovery surface to a LiteLLM Gateway
    Primary runtimes: SGLang and vLLM on internal Kubernetes services
    Design date: 2026-08-14

    1. Goal¶

    Implement a new, clearly separated OpenRouter-compatible model-discovery API in LiteLLM:

    GET /api/v1/models

    The endpoint must:

    1. Return the current OpenRouter Models API response shape.
    2. Discover live deployment information from the actual upstream inference runtime.
    3. Support SGLang and vLLM first.
    4. Be extensible to other runtimes and hosted providers later.
    5. Reuse LiteLLM's existing pricing/model registry logic rather than creating a second pricing database.
    6. Avoid persistent state in the first implementation.
    7. Keep runtime-specific parsing separate from OpenRouter serialization.
    8. Preserve LiteLLM authorization/model-access behavior.
    9. Remain resilient when an upstream model server is unavailable.
    10. Be maintainable as OpenRouter, vLLM, SGLang, and LiteLLM evolve.

    The public API contract is OpenRouter-compatible. The internal implementation must not be coupled to OpenRouter's data model.

    2. Non-negotiable architectural decisions¶

    2.1 Keep /v1/models unchanged¶

    Keep LiteLLM's existing OpenAI-compatible endpoint:

    GET /v1/models

    Add the richer compatibility surface separately:

    GET /api/v1/models

    Future OpenRouter-compatible routes should live under the same namespace:

    /api/v1/models
/api/v1/models/{author}/{slug}/endpoints
/api/v1/models/{slug}/endpoints

    This avoids breaking normal OpenAI-compatible clients and gives OpenRouter-specific behavior a clean boundary.

    2.2 Runtime metadata is live and ephemeral¶

    Do not initially persist runtime facts such as:

    • actual served model ID;
    • actual deployment context length;
    • runtime version;
    • runtime-supported task routes;
    • SGLang image/audio understanding;
    • OpenAPI-discovered API surface.

    Initial flow:

    request
  -> resolve caller-visible LiteLLM deployments
  -> query live upstream runtime
  -> normalize
  -> enrich from LiteLLM registry/pricing
  -> aggregate
  -> map into OpenRouter response
  -> discard

    A cache can be added later, but it is an optimization, not the source of truth.

    2.3 OpenRouter owns the output schema¶

    Do not maintain a handwritten copy of OpenRouter's Model type.

    Use the official generated Python SDK as the output-contract dependency:

    from openrouter.components.model import Model as OpenRouterModel

    OpenRouter's official generated source is marked Code generated by Speakeasy ... DO NOT EDIT.

    Pin the SDK to a tested version in the image/build. Upgrade it through Renovate/Dependabot or an equivalent controlled dependency workflow.

    Do not dynamically clone OpenRouter, install latest, or generate code at application startup.

    2.4 Our code owns the mapper, not the OpenRouter schema¶

    Ownership boundary:

    OpenRouter owns:
  API schema
  generated SDK types

Our LiteLLM extension owns:
  discovery
  normalization
  aggregation
  pricing enrichment
  mapping
  failure policy
  caching

    When OpenRouter adds an optional field, an SDK upgrade should usually remain compatible. When it adds a required field, contract tests should fail until the mapper has an explicit policy. That failure is desirable.

    2.5 Never map runtime JSON directly into OpenRouter¶

    Use four layers:

    1. Raw runtime DTOs
2. DiscoveredDeploymentModel
3. AggregatedModel
4. OpenRouter generated output model

    Dependency direction only:

    raw DTO -> canonical deployment -> aggregation -> OpenRouter mapper

    3. Verified runtime behavior¶

    3.1 SGLang v0.5.16¶

    /v1/models exposes:

    id
object
created
owned_by
root
parent
max_model_len

    /model_info exposes richer facts:

    model_path
tokenizer_path
is_generation
preferred_sampling_params
weight_version
has_image_understanding
has_audio_understanding
model_type
architectures

    /get_model_info remains a deprecated alias for /model_info.

    Therefore SGLang discovery should use:

    /v1/models
/model_info
/openapi.json       optional

    3.2 vLLM v0.24.0¶

    /v1/models exposes:

    id
object
created
owned_by
root
parent
max_model_len
permission

    vLLM does not expose a normal production /model_info endpoint equivalent to SGLang's richer endpoint.

    Current vLLM builds parts of its FastAPI surface from supported_tasks; generation, speech-to-text/realtime, and pooling route groups are conditionally registered. Therefore /openapi.json can be useful for API/task capability discovery.

    However, vLLM can disable OpenAPI/docs with:

    --disable-fastapi-docs

    so the OpenAPI probe must be optional.

    5. Canonical internal domain model¶

    Use composition for capabilities. Use inheritance only for discovery protocol behavior.

    5.1 Identity¶

    class ModelIdentity(BaseModel):
    logical_model_name: str
    upstream_model_id: str | None = None

    root: str | None = None
    parent: str | None = None

    display_name: str | None = None
    canonical_id: str | None = None
    hugging_face_id: str | None = None
    created: int | None = None

    Rules:

    • logical_model_name is the LiteLLM-facing routable name.
    • upstream_model_id is what vLLM/SGLang reports.
    • root is internal only. vLLM may expose a filesystem path there.
    • Never return PVC paths, tokenizer paths, ClusterIP addresses, or other internal identifiers publicly.

    5.2 Limits¶

    class ModelLimits(BaseModel):
    context_length: int | None = None
    max_input_tokens: int | None = None
    max_completion_tokens: int | None = None

    Keep all three concepts separate.

    For current vLLM/SGLang:

    max_model_len -> context_length

    Do not generically alias arbitrary fields such as max_tokens, max_input_tokens, and max_model_len because their semantics can differ.

    5.3 Architecture¶

    class ModelArchitecture(BaseModel):
    model_type: str | None = None
    architectures: list[str] = Field(default_factory=list)
    tokenizer: str | None = None
    instruct_type: str | None = None

    SGLang /model_info can populate model_type and architectures even though OpenRouter does not expose those exact internal fields.

    5.4 Model capabilities¶

    Do not create classes such as VisionModel, AudioModel, or VisionAudioModel.

    class ModelCapabilities(BaseModel):
    input_modalities: set[str] | None = None
    output_modalities: set[str] | None = None

    tool_calling: bool | None = None
    parallel_tool_calling: bool | None = None
    reasoning: bool | None = None
    structured_outputs: bool | None = None
    logprobs: bool | None = None
    embeddings: bool | None = None
    rerank: bool | None = None

    is_moderated: bool | None = None
    supported_parameters: set[str] | None = None
    supported_voices: list[str] | None = None

    Preserve tri-state semantics:

    True  = explicitly supported
False = explicitly unsupported
None  = unknown

    Never translate omission into False.

    5.5 API capabilities¶

    Keep server/API capability separate from model capability:

    class ApiCapabilities(BaseModel):
    chat_completions: bool | None = None
    completions: bool | None = None
    responses: bool | None = None
    embeddings: bool | None = None
    transcription: bool | None = None
    speech: bool | None = None
    rerank: bool | None = None
    classification: bool | None = None
    routes: set[str] = Field(default_factory=set)

    Meaning:

    /openapi.json -> what the server API exposes
/model_info   -> what the loaded model can actually understand

    Those are not equivalent.

    5.6 Runtime information¶

    class RuntimeInfo(BaseModel):
    kind: str
    version: str | None = None
    deployment_id: str
    api_base_fingerprint: str | None = None

    Never expose the real private api_base in public output.

    5.7 Provenance¶

    Recommended:

    class FactSource(BaseModel):
    probe: str
    field: str | None = None

class ModelProvenance(BaseModel):
    facts: dict[str, FactSource] = Field(default_factory=dict)

    Examples:

    limits.context_length
  <- OpenAIModelsProbe.max_model_len

capabilities.input_modalities.image
  <- SGLangModelInfoProbe.has_image_understanding

    Keep provenance internal.

    5.8 Canonical deployment object¶

    class DiscoveredDeploymentModel(BaseModel):
    identity: ModelIdentity
    limits: ModelLimits
    architecture: ModelArchitecture
    capabilities: ModelCapabilities
    api_capabilities: ApiCapabilities
    runtime: RuntimeInfo
    provenance: ModelProvenance

    Every runtime/provider adapter must eventually return this type.

    6. Upstream transport DTOs¶

    External runtime responses must be permissive because new versions may add fields.

    class UpstreamDTO(BaseModel):
    model_config = ConfigDict(extra="allow")

    Common OpenAI-compatible card:

    class OpenAICompatibleModelCard(UpstreamDTO):
    id: str
    object: str | None = None
    created: int | None = None
    owned_by: str | None = None
    root: str | None = None
    parent: str | None = None

class RuntimeModelCard(OpenAICompatibleModelCard):
    max_model_len: int | None = None

    vLLM:

    class VLLMModelCard(RuntimeModelCard):
    permission: list[dict] = Field(default_factory=list)

    SGLang:

    class SGLangModelCard(RuntimeModelCard):
    pass

class SGLangModelInfo(UpstreamDTO):
    model_path: str | None = None
    tokenizer_path: str | None = None
    is_generation: bool | None = None
    preferred_sampling_params: dict | None = None
    weight_version: str | None = None
    has_image_understanding: bool | None = None
    has_audio_understanding: bool | None = None
    model_type: str | None = None
    architectures: list[str] | None = None

    7. Discovery adapter hierarchy¶

    Use inheritance for protocol behavior:

    BaseDiscoveryAdapter
│
├── RuntimeDiscoveryAdapter
│   └── OpenAICompatibleRuntimeAdapter
│       ├── VLLMDiscoveryAdapter
│       ├── SGLangDiscoveryAdapter
│       ├── future TGIAdapter
│       ├── future TensorRTLLMAdapter
│       └── future LlamaCppAdapter
│
└── ProviderDiscoveryAdapter
    ├── OpenAICompatibleProviderAdapter
    │   └── future XAIAdapter
    ├── future AnthropicAdapter
    ├── future BedrockAdapter
    └── future VertexAdapter

    Do not create adapters named after individual model families such as ClaudeAdapter or GrokAdapter. The adapter represents the discovery protocol/provider/runtime, not one model.

    Template:

    class BaseDiscoveryAdapter(ABC):

    async def discover(self, deployment):
        raw_models = await self.discover_models(deployment)

        models = [
            self.normalize_model(deployment, raw)
            for raw in raw_models
        ]

        return await self.enrich(deployment, models)

    @abstractmethod
    async def discover_models(self, deployment):
        ...

    @abstractmethod
    def normalize_model(self, deployment, raw):
        ...

    async def enrich(self, deployment, models):
        return models

    8. Reusable probes¶

    Adapters should orchestrate reusable probes rather than duplicate HTTP behavior.

    Implement:

    OpenAIModelsProbe
  GET /v1/models

OpenAPISchemaProbe
  GET /openapi.json

SGLangModelInfoProbe
  GET /model_info
  fallback GET /get_model_info

    Probe result should carry:

    success/failure
data
source/probe name
latency
error category

    An optional probe failure must not fail the complete model catalog.

    9. vLLM adapter¶

    Initial probe set:

    /v1/models
/openapi.json optional

    Map:

    id             -> identity.upstream_model_id
created        -> identity.created
root           -> internal identity.root only
parent         -> identity.parent
max_model_len  -> limits.context_length
owned_by       -> runtime-detection hint only

    Do not use permission as modality/capability metadata.

    9.1 vLLM OpenAPI enrichment¶

    If /openapi.json exists, inspect:

    paths
HTTP methods
operationId
requestBody
components.schemas

    Examples of useful API-surface evidence:

    /v1/chat/completions      -> chat_completions API available
/v1/embeddings            -> embeddings API available
/v1/audio/transcriptions  -> transcription API available

    Because vLLM conditionally registers some router groups from supported_tasks, route presence can be meaningful.

    But:

    /v1/chat/completions exists

    is not proof that the loaded model is text-only. Vision/multimodal models can use the same endpoint.

    Treat OpenAPI as API/task evidence, not universal model-modality truth.

    10. SGLang adapter¶

    Probe set:

    /v1/models
/model_info
/openapi.json optional

    Base mapping is the same as vLLM for id, created, root, parent, and max_model_len.

    Enrich from /model_info:

    has_image_understanding = true
  -> add image input modality

has_audio_understanding = true
  -> add audio input modality

model_type
  -> architecture.model_type

architectures
  -> architecture.architectures

    For the current DeepSeek SGLang deployment, explicit false values for image/audio are meaningful negatives because SGLang derives them from the loaded model config.

    Support /get_model_info only as a fallback for older SGLang versions.

    11. Runtime detection¶

    Prefer:

    1. explicit deployment metadata override
2. known provider/runtime configuration
3. /v1/models owned_by hint
4. safe probing
5. generic OpenAI-compatible fallback

    Optional LiteLLM metadata:

    model_info:
  discovery_runtime: sglang

    or:

    model_info:
  discovery_runtime: vllm

    Do not require this field, but allow it to avoid guessing.

    Do not build the primary logic around version comparisons such as:

    if sglang_version >= ...

    Use capability probing:

    try /model_info
fallback /get_model_info
otherwise continue without native enrichment

    Capture runtime version for diagnostics only.

    12. OpenAPI probe rules¶

    Create one reusable inspector:

    class OpenAPIInspector:
    def has_path(self, path: str) -> bool: ...
    def has_operation(self, path: str, method: str) -> bool: ...
    def request_schema_mentions(self, path: str, symbol: str) -> bool: ...
    def parameter_names(self, path: str, method: str) -> set[str]: ...

    V1 does not need a complete OpenAPI engine. Resolve enough local $ref references to inspect known request schemas.

    Useful schema signals may include:

    tools
tool_choice
parallel_tool_calls
response_format
reasoning
logprobs

    But remember:

    schema supports field != loaded model supports field

    13. Evidence precedence¶

    Use deterministic source precedence.

    For live runtime/model facts:

    1. explicit runtime-native loaded-model metadata
2. live runtime /v1/models
3. runtime OpenAPI route/schema evidence
4. explicit LiteLLM deployment model_info override
5. LiteLLM model registry
6. unknown

    For pricing:

    1. explicit LiteLLM deployment pricing/config
2. existing LiteLLM cost/model registry lookup
3. explicit configured fallback/unknown policy

    Never let theoretical registry context overwrite a smaller live deployment context.

    Example:

    LiteLLM registry: 262144
vLLM max_model_len: 65536

advertise deployment context: 65536

    14. LiteLLM pricing integration¶

    Reuse your existing LiteLLM pricing path. Do not create another model price database.

    Introduce a thin resolver interface:

    class PricingResolver:
    async def resolve(self, logical_model, deployment):
        ...

    Reuse current LiteLLM logic backed by its continuously maintained model_prices_and_context_window.json data and explicit deployment overrides.

    OpenRouter currently requires pricing.prompt and pricing.completion in the Model object.

    Define explicit behavior if pricing is unknown. Do not silently report zero unless zero is truly the gateway's billing semantics.

    15. LiteLLM deployment resolver and authorization¶

    Create:

    class LiteLLMDeploymentResolver:
    async def resolve_for_request(self, auth_context):
        ...

    Return a minimal descriptor:

    class DeploymentDescriptor(BaseModel):
    deployment_id: str
    logical_model_name: str
    provider: str | None = None
    model: str | None = None
    api_base: str | None = None
    auth_headers: dict[str, str] | None = None
    model_info: dict = Field(default_factory=dict)

    The new endpoint must reuse LiteLLM's current authentication and model-access filtering.

    Security invariant:

    A model the caller cannot invoke must not appear in /api/v1/models.

    Filter inaccessible logical models before discovery fan-out.

    Do not independently reimplement all key/team/user/access-group rules; call the same current LiteLLM helpers used by the proxy branch you are modifying.

    16. SSRF and upstream URL safety¶

    Discovery performs server-side HTTP requests, therefore discovery targets must come only from trusted LiteLLM deployment configuration.

    Never accept discovery targets from:

    query parameters
request body
model ID
user headers

    There must never be a feature like:

    GET /api/v1/models?api_base=http://arbitrary-host

    If untrusted tenants can create deployments, add a network/host allowlist policy before enabling live probes.

    17. HTTP transport¶

    Use a shared async HTTP client with connection pooling.

    class DiscoveryHTTPClient:
    async def get_json(self, deployment, path, *, timeout):
        ...

    Requirements:

    • shared connection pool;
    • short configurable connect/read timeouts;
    • upstream auth support;
    • bounded concurrency;
    • response-size cap, especially for OpenAPI;
    • JSON validation;
    • clear timeout/HTTP/parse error categories;
    • no secrets in logs.

    Suggested starting timeout range: 1-3 seconds per probe, configurable.

    18. Concurrency and deduplication¶

    Do not discover deployments serially.

    Use bounded async fan-out:

    results = await asyncio.gather(
    *tasks,
    return_exceptions=True,
)

    with a semaphore.

    Deduplicate identical discovery targets. If several LiteLLM deployments point to the same api_base + runtime + auth identity, one /openapi.json fetch should be reusable during the request/cache lifetime.

    19. Kubernetes ClusterIP invariant¶

    For V1, all replicas behind one inference Service should expose equivalent identity/capabilities/limits.

    Good:

    qwen-service
  pod A 262144
  pod B 262144
  pod C 262144

    Unsafe:

    qwen-service
  pod A 262144
  pod B 65536
  pod C 32768

    A heterogeneous Service makes ClusterIP discovery nondeterministic.

    Document homogeneous replicas as a V1 requirement. If heterogeneous replicas are needed later, query EndpointSlices/pods and model them as distinct deployments.

    20. Aggregation layer¶

    Discovery returns deployments. /api/v1/models returns logical models.

    Example:

    LiteLLM model_name = qwen-coder

  deployment A: vLLM   context 262144
  deployment B: SGLang context 131072

    Keep both deployment objects, then aggregate:

    class ModelAggregator:
    def aggregate(self, logical_model_name, deployments):
        ...

    Canonical logical object:

    class AggregatedModel(BaseModel):
    logical_model_name: str
    deployments: list[DiscoveredDeploymentModel]
    identity: ModelIdentity
    limits: ModelLimits
    architecture: ModelArchitecture
    capabilities: ModelCapabilities
    pricing: object | None = None

    21. Conservative aggregation policies¶

    Keep policies explicit in aggregation/policies.py.

    21.1 Context length¶

    Default policy:

    guaranteed logical context = minimum known context across eligible routable deployments

    Reason: advertising the maximum is unsafe if LiteLLM can route the request to a smaller-context deployment.

    Allow a configurable alternative only if routing semantics justify it:

    class ContextAggregationPolicy(str, Enum):
    GUARANTEED_MIN = "guaranteed_min"
    MAX_AVAILABLE = "max_available"

    Default to GUARANTEED_MIN.

    21.2 Completion limit¶

    Apply the same conservative principle when multiple explicit limits exist.

    21.3 Modalities/capabilities¶

    If LiteLLM may route any request to any deployment, the logical model should advertise capabilities guaranteed across all eligible deployments.

    Example:

    A = text+image
B = text only

    Do not advertise image at the logical level unless routing is capability-aware and guarantees image requests reach A.

    The per-deployment endpoint can expose richer deployment-specific capabilities.

    22. Unknown vs unsupported at OpenRouter boundary¶

    Keep None internally for unknown.

    OpenRouter's architecture.input_modalities and output_modalities are required arrays, so define one explicit mapper policy.

    Recommended resolution before mapping:

    runtime-native metadata
  -> OpenAPI/task evidence
  -> LiteLLM exact-model registry fallback
  -> unknown

    If still unknown, either:

    1. emit an empty list without making a false claim, or
    2. in strict mode, omit the model because required architecture semantics are insufficiently known.

    Make this configurable. Do not silently invent text just because a field is missing.

    24. OpenRouter SDK integration¶

    Prefer normal package dependency installation rather than copying one generated file.

    openrouter.components.model.Model depends on generated sibling classes and OpenRouter SDK helper types, so copying only model.py is not maintainable.

    Recommended:

    pin official openrouter Python SDK version

    25. OpenRouter mapper¶

    Only this layer imports OpenRouter generated classes.

    class OpenRouterModelMapper:
    def map_model(self, model: AggregatedModel) -> OpenRouterModel:
        ...

    Discovery adapters must never import OpenRouter types.

    Current required OpenRouter Model fields include:

    Required-but-nullable fields include several fields such as context_length, per_request_limits, default_parameters, and supported_voices.

    Use OpenRouter's generated serializer so nullable/optional behavior follows their contract.

    26. Current /api/v1/models list shape¶

    At the time of this design, OpenRouter's list response requires:

    {
  "data": [],
  "total_count": 0,
  "links": {
    "next": null
  }
}

    Implement pagination arguments if clients may request them. At minimum, data, total_count, and links.next must be correct.

    27. Public ID and canonical slug¶

    The public id should remain LiteLLM's routable logical model_name, because clients will use the discovered ID for inference.

    OpenRouterModel.id = LiteLLM logical model_name

    For a bare alias such as:

    qwen-coder

    use a stable canonical namespace such as:

    canonical_slug = litellm/qwen-coder

    If the existing logical ID is already provider-like (qwen/qwen3.5), it may be used directly if stable.

    Do not rewrite id into a value that LiteLLM inference does not accept.

    28. Display name and created timestamp¶

    Name priority:

    1. configured display name
2. registry display name
3. upstream model ID
4. logical LiteLLM model name

    For created, use a deterministic known runtime/deployment timestamp. Do not claim it is the model's release date unless you have actual release metadata. Runtime ModelCard creation timestamps may reflect server/model-card creation.

    29. top_provider policy¶

    Treat top_provider as the gateway's representative/guaranteed serving capability:

    top_provider.context_length
  = aggregated guaranteed context

top_provider.max_completion_tokens
  = aggregated guaranteed completion limit

    OpenRouter requires top_provider.is_moderated as a boolean. Since internal state may be unknown, define an explicit gateway policy/config default rather than accidentally turning None into False inside arbitrary code.

    30. architecture mapping¶

    OpenRouter currently requires:

    modality
input_modalities
output_modalities

    Keep OpenRouter-specific formatting in the mapper.

    Do not make runtime adapters know OpenRouter enum conventions.

    Internal SGLang fields such as:

    model_type = deepseek_v4
architectures = [DeepseekV4ForCausalLM]

    remain useful internal data even if not emitted by OpenRouter's current schema.

    31. Model endpoint-details route¶

    OpenRouter's required links.details points to a per-model endpoints resource.

    Implement immediately after the list route:

    GET /api/v1/models/{author}/{slug}/endpoints
GET /api/v1/models/{slug}/endpoints

    The second form serves a model whose id has no author segment, e.g. hamsa-tts. The mapper namespaces such ids under litellm, so hamsa-tts is canonically litellm/hamsa-tts and the first form serves that. The bare form is accepted too so a client that reads the id straight from /v1/models does not have to know about the namespace. Both forms return the same body, keyed by the canonical id.

    This route should use AggregatedModel.deployments and expose deployment/provider-specific limits/pricing/capabilities according to the current OpenRouter endpoint schema.

    Do not return a permanently dead links.details URL.

    The match key is the LiteLLM routing name, not the upstream served id¶

    {author}/{slug} is matched against the registered model_name, the string a caller puts in the request body. Re-joining author and slug reproduces it exactly, so the URL round-trips into a working request. A model registered without an author segment is canonically namespaced under litellm.

    This is deliberately not the upstream served id, which the runtime reports at /v1/models and which can differ. Live example:

    litellm model_name (routing, request body)  Qwen/Qwen-Image-2.1
upstream /v1/models id (served)             Qwen-Image-2.1

    Matching on the routing name is the only workable choice, because LiteLLM rejects the served name outright:

    POST /v1/images/generations {"model": "Qwen-Image-2.1"}
  -> 400 Invalid model name passed in model=Qwen-Image-2.1

    Keying the URL on the served id would therefore make the URL reject the very string the request body needs. The served id is still surfaced, as the endpoint's model_name field.

    Do not assume a runtime validates model. Verified on the dev cluster: sending a deliberately bogus name straight to the upstream still returns HTTP 200 for both image generation (vLLM omni) and chat completions (SGLang). The upstream serves whatever it has loaded and ignores the field, which is the only reason the routing-name/served-id mismatch is invisible today. If a runtime ever starts validating model, the image model above breaks at that layer, and nothing in this code reconciles the two names.

    model_name is not unique: several deployments can share it when the same model is served from more than one cluster. Routing on it is correct, LiteLLM load-balances across those deployments, and one URL then returns one endpoint object per deployment.

    Never expose ClusterIP addresses, local filesystem paths, credentials, or private service names unless deliberately part of your public API.

    32. Upstream authentication¶

    Discovery must support private model runtimes when needed.

    Reuse LiteLLM's resolved deployment credentials/headers.

    Do not put secrets in:

    logs
client errors
public provenance
plain-text cache keys

    Use a hash/fingerprint if auth identity must participate in deduplication/cache keys.

    33. Failure behavior¶

    Default behavior should be resilient:

    fan out discovery
collect successful deployments
log/measure failed probes
aggregate remaining deployments
return partial catalog

    If one of several deployments fails, use the healthy ones.

    If all deployments for a logical model fail:

    fallback to sufficient LiteLLM config/registry metadata
otherwise omit the model in strict mode

    Do not fabricate a live context limit after total discovery failure.

    Internal error categories:

    DiscoveryTimeout
DiscoveryConnectionError
DiscoveryHTTPError
DiscoveryInvalidJSON
DiscoverySchemaError
UnsupportedRuntime
MissingRequiredOpenRouterField

    34. Caching¶

    V1 may begin uncached if deployment count is small, but code interfaces should allow cache insertion.

    Recommended cache key dimensions:

    deployment identity
runtime kind
api_base fingerprint
auth identity fingerprint

    Good cache targets:

    raw /v1/models
raw /model_info
parsed OpenAPI capabilities
final DiscoveredDeploymentModel

    Initial TTL when enabled:

    5-30 seconds

    No Postgres is needed.

    Prefer caching deployment discovery and applying caller authorization/aggregation afterward. Never globally cache one caller's filtered model list and serve it to another caller.

    41. Service orchestration pseudocode¶

    class OpenRouterModelsService:

    async def list_models(
        self,
        auth_context,
        *,
        offset: int = 0,
        limit: int = 500,
    ):
        deployments = await self.deployment_resolver.resolve_for_request(
            auth_context
        )

        discoveries = await self.discovery_service.discover_many(
            deployments
        )

        discoveries = await self.metadata_enricher.enrich(
            discoveries
        )

        discoveries = await self.pricing_enricher.enrich(
            discoveries
        )

        models = self.aggregator.aggregate_all(discoveries)

        output = [
            self.mapper.map_model(model)
            for model in models
        ]

        total_count = len(output)
        page = output[offset:offset + limit]

        return {
            "data": page,
            "total_count": total_count,
            "links": {
                "next": build_next_link(
                    offset=offset,
                    limit=limit,
                    total_count=total_count,
                )
            },
        }

    42. Discovery orchestration pseudocode¶

    class DiscoveryService:

    async def discover_many(self, deployments):
        targets = deduplicate_targets(deployments)

        results = await asyncio.gather(
            *[
                self._discover_target(target)
                for target in targets
            ],
            return_exceptions=True,
        )

        return merge_discovery_results(
            deployments,
            targets,
            results,
        )

    async def _discover_target(self, deployment):
        adapter = self.registry.resolve(deployment)
        return await adapter.discover(deployment)

    43. Future extension rule¶

    Adding a new runtime such as TensorRT-LLM should require only:

    1. unique transport DTO(s), if needed
2. a discovery adapter
3. optional native probe(s)
4. registry entry
5. tests

    It should not require changing:

    /api/v1/models route
OpenRouter public contract
SGLang adapter
vLLM adapter
canonical domain model

    unless the new runtime introduces a genuinely new capability dimension.

    Hosted providers belong under ProviderDiscoveryAdapter, not under runtime adapters.

    44. What not to do¶

    • [ ] Do not turn LiteLLM /v1/models into OpenRouter's schema.
    • [ ] Do not persist live SGLang/vLLM limits as the initial source of truth.
    • [ ] Do not create a second pricing database.
    • [ ] Do not copy only OpenRouter's model.py.
    • [ ] Do not generate/install schema code at runtime.
    • [ ] Do not map SGLang/vLLM JSON directly into OpenRouter output.
    • [ ] Do not infer vision=False from a missing vLLM field.
    • [ ] Do not treat route presence as proof of every modality.
    • [ ] Do not expose root/model/tokenizer paths or ClusterIP details.
    • [ ] Do not query arbitrary caller-supplied URLs.
    • [ ] Do not perform serial discovery fan-out.
    • [ ] Do not fail the whole catalog because one optional probe failed.
    • [ ] Do not use runtime-version conditionals as the primary adapter mechanism.
    • [ ] Do not silently turn unknown into zero/false.
    • [ ] Do not globally cache caller-specific authorization results.

    45. Definition of done¶

    • [ ] GET /api/v1/models exists separately from /v1/models.
    • [ ] Output validates against the pinned official OpenRouter Python SDK.

    • [ ] SGLang /model_info enriches image/audio/model architecture facts.
