    Hamsa TTS New: /v1 Endpoint Guide¶

    Scope: How to call hamsa-tts-new text-to-speech through the LiteLLM gateway, with sample curl commands and expected response shapes

    Related docs: HAMSA_STT_GUIDE.md (hamsa-stt usage), GATEWAY_GUIDE.md (gateway overview)

    This is the active Hamsa TTS model. The original hamsa-tts deployment is retired and removed from the gateway: its backend Service no longer exists and its model row was deleted on dev and prod, so requests for it now fail with HTTP 400 "Invalid model name" (verified 2026-10-21). Use hamsa-tts-new.

    Gateway URL: https://litellm.ecouncil.ae (valid DigiCert wildcard *.ecouncil.ae cert; curl -k is not required)

    API Key: replace <your-api-key> everywhere below with your LiteLLM gateway API key. All requests use the Authorization: Bearer <your-api-key> header.

    Model: hamsa-tts-new

    Verified: 2026-10-21

    Gateway endpoints¶

    The gateway supports two /v1 endpoints for this model:

    Endpoint Method Purpose
    /v1/models GET List available models
    /v1/audio/speech POST Synthesize speech (WAV)

    No other /v1 endpoints (voices, voice-clone, status, ...) are exposed on the gateway.

    List models¶

    curl -sk "https://litellm.ecouncil.ae/v1/models" \
  -H "Authorization: Bearer <your-api-key>"

    Response (trimmed):

    {
  "object": "list",
  "data": [
    { "id": "hamsa-tts-new", "object": "model", "owned_by": "ADEO" }
  ]
}

    Synthesize speech (TTS)¶

    Endpoint¶

    POST /v1/audio/speech

    Request shape¶

    Returns WAV audio (16-bit mono 16 kHz PCM). Save the binary response to a file because the response body is raw audio, not JSON.

    Field Required Default Notes
    model yes Must be hamsa-tts-new
    input yes Text to synthesize (Arabic or English)
    voice yes Speaker name — see voice list below
    response_format no wav wav or pcm (with stream)
    speed no 1.0 0.5 – 2.0
    expressiveness no 1.0 0.0 – 2.0
    stream no false true returns raw headerless 16-bit 16 kHz mono PCM, delivered in chunks as synthesis proceeds (first chunk in ~300 ms). Send response_format: "pcm" so the gateway labels the body audio/pcm

    Sample curl¶

    curl -sk -X POST "https://litellm.ecouncil.ae/v1/audio/speech" \
  -H "Authorization: Bearer <your-api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "hamsa-tts-new",
    "input": "مرحبا بكم في مجلس أبوظبي",
    "voice": "Zeina",
    "response_format": "wav"
  }' \
  -o speech.wav

    Response¶

    Binary audio with Content-Type: audio/wav. Verified result:

    HTTP 200 — speech.wav: RIFF (little-endian) data, WAVE audio,
Microsoft PCM, 16 bit, mono 16000 Hz

    Note: the WAV header contains 0xFFFFFFFF in the RIFF/data size fields (streaming-style header from the backend). ffprobe, file and audio players read it fine, but Python's built-in wave module misreports the duration. If you need exact size, trust the file length, not the header.

    Streaming (low-latency playback)¶

    "stream": true makes the backend synthesize and ship audio in chunks: the first bytes arrive in ~300 ms instead of at the end of synthesis, and the body is raw 16-bit PCM, 16 kHz mono, with no WAV header. The gateway relays the chunks as they arrive (Content-Type: audio/pcm when you also send "response_format": "pcm").

    curl -sk -N -X POST "https://litellm.ecouncil.ae/v1/audio/speech" \
  -H "Authorization: Bearer <your-api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "hamsa-tts-new",
    "input": "مرحبا بكم في مجلس أبوظبي",
    "voice": "Zeina",
    "response_format": "pcm",
    "stream": true
  }' \
  -o speech.pcm

    Measure the first-byte latency with curl -w (expect time_starttransfer well below time_total, roughly 0.3 s on a multi-second synthesis):

    curl -sk -N -o /dev/null -X POST "https://litellm.ecouncil.ae/v1/audio/speech" \
  -H "Authorization: Bearer <your-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"hamsa-tts-new","input":"...","voice":"Zeina","response_format":"pcm","stream":true}' \
  -w "TTFB=%{time_starttransfer}s TOTAL=%{time_total}s\n"

    More examples¶

    Different voice:

    curl -sk -X POST "https://litellm.ecouncil.ae/v1/audio/speech" \
  -H "Authorization: Bearer <your-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"hamsa-tts-new","input":"السلام عليكم","voice":"Amir","response_format":"wav"}' \
  -o amir.wav

    Faster and more expressive:

    curl -sk -X POST "https://litellm.ecouncil.ae/v1/audio/speech" \
  -H "Authorization: Bearer <your-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"hamsa-tts-new","input":"أهلا وسهلا","voice":"Layla","speed":1.3,"expressiveness":1.5,"response_format":"wav"}' \
  -o layla.wav

    Errors¶

    Case HTTP Body
    Unknown voice 400 speaker_not_found: speaker 'X' not loaded
    Missing/wrong key 401 auth_error
    Key without model access 403 key_model_access_denied
    Empty input 400/422 validation error

    OpenAI SDK (Python)¶

    Verified live with openai SDK 3.9.0 against the gateway:

    from openai import OpenAI

client = OpenAI(
    base_url="https://litellm.ecouncil.ae/v1",
    api_key="<your-api-key>",
)

with client.audio.speech.with_streaming_response.create(
    model="hamsa-tts-new",
    voice="Zeina",
    input="أهلا وسهلا",
) as response:
    response.stream_to_file("speech.wav")

    Verified result:

    client.models.list()   -> ['hamsa-tts-new']
speech.wav             -> RIFF WAVE, Microsoft PCM, ~31 KB, 0.98 s (ffprobe)
